# Original workstation settings — integration and evidence

Hook: `new OriginalWorkstationSettingsStore(connectionString, () => currentAuthenticatedActor, () => currentSessionPin)` → `new OriginalWorkstationSettingsWorkflow(store)` → `new OriginalWorkstationSettingsDialog(workflow) { Owner = hostWindow }.ShowDialog()`. Root must retain its existing modal/session guard. No extra PIN prompt: the backend reads the session PIN once per authorization check, releases that local reference, and verifies exact current credentials and ADMIN role on both load and save. A revoked role, changed session or changed PIN refuses writes.

Source authority: Form_9_PARAMETRE1194–1239 delegates to FormDialog_2_Configuration, FormDialog_3_Configuration_Suite and FormDialog_4_Configuration_Suite. Configuration2391–2403 reads payment, stock correction, closing, ticket/connection flags; Configuration_Suite1529–1540 reads receipt flags/footer. The original input/recovered-original.sql3787 defaults MODIF_STOCK_MANUEL, GESTION_CLOTURE and CLOTURE_CAISSIER_OBLIGER to False. FormDialog_FONDS_CAISSE1424–1433 reads FONDS_CAISSE and uses zero for no database value. Missing four fields are displayed with those explicit defaults, but loading does not insert them. Enregistrer inserts only explicitly submitted missing fields in the same serializable CAS transaction. No wholesale parameter initialization or silent migration occurs.

Wired consumers: MODELE_TICKET/BRANCHEMENT → LogicaReceiptSettings and ReceiptPrintRouting (new routes limited to FR_3C/USB); AFFICHER_MODE_P/AFFICHER_N_TICKET/AFFICHER_CODE_BARRE/PIED_TICKET → LogicaCashReceiptPrinter; FENETRE_MODE_P → MariaDbCashCheckoutPreparation.RequireCardMode; MODIF_STOCK_MANUEL → recovered Infrastructure/Inventory/StockAdjustmentWriter145; GESTION_CLOTURE/CLOTURE_CAISSIER_OBLIGER/FONDS_CAISSE → CashDrawerClosing198–205. Numeric funds use the existing TouchNumericEntry keypad, including current-culture display and invariant persisted amount. Existing raw boolean -1 remains unchanged when untouched.

Other original settings (display ports, scale ports, email, kitchen printers, RFID, group/table management, seller selection, alternative ticket layouts) lack complete HANOUTY consumers and are deliberately not editable here. Existing local printer selection is a separate already delivered dialog. No invented NOM_MAGASIN/RAISON_SOCIALE/ADRESSE/TELEPHONE keys were found in TABLE_PARAMETRES/source. Form_3_VENTE11934 sets Picture_LOGO from Form_0_TEMPLATE.logo_ar_vente_logo, while current LogicaReceiptRenderer uses embedded LogicaReceiptLogo.jpg. Editable store branding/logo requires an original-backed asset consumer and remains an explicit gap; this package does not claim to deliver it.

Standalone OriginalWorkstationSettingsAcceptance project executes only its own disposable MariaDB33082 schema with original seven-field baseline. It verifies eleven settings, explicit default insertion, read-only load, UTF8, exact/raw boolean preservation, idempotent retry, stale CAS refusal, transaction rollback after a second-update failure, wrong session PIN, revoked role, lookalike identity and unknown-key refusal. Real WPF dialog + existing numeric keypad are opened and exercised, and a screenshot/proof are emitted. No shop database, main/release, existing DailyLogicaSettings or shared UI/Host files changed. No commit was made per instruction.
