# Protected local LOGICA copy

The wizard calls `ProtectedLocalCopyService.PrepareAsync` on a worker thread. Existing profile selection stays unchanged on refusal. Activate the NEW database only when `Ready && SourceUnchanged`; this does not validate catalogue image paths, licensing, local printer or shop hardware.

Pass eleven `ProtectedCopyMigration(Name, Sql, Sha256)` resources, normalized LF and SHA256 of UTF8 text. The service pins both names and hashes to the reviewed SQL, so arbitrary SQL cannot be supplied through this API. Embed the existing ten migrations plus `20261121-checkout-and-full-return-journals.sql` using stable `Hanouty.Migrations.<filename>.sql` resource names. No repository path is used by the installed service.

Source and destination use the same explicitly selected loopback server. A source SELECT-only account is supported and tested; a broader account is allowed, but source commands remain SELECT/SHOW and session READ ONLY. The dump uses a private `--defaults-file` as its FIRST argument, `--single-transaction --skip-lock-tables --skip-add-locks --skip-add-drop-table --skip-disable-keys --skip-comments --skip-triggers --skip-events --skip-routines --hex-blob --no-tablespaces`. Global my.ini files are not inherited. Passwords are not arguments, progress, journal or exception text. The newly and atomically created job folder has only the current user's inherited ACL. Temporary credentials are removed in finally. Backup and journal are intentionally retained privately, including on failure.

Refusals: nonlocal host, existing destination or folder, traversal/links, unsupported executable SQL objects, generated columns, cross-database foreign keys, any non-InnoDB source table, incomplete required LOGICA schema/numeric fields, nonempty selected basket, unsupported counters, changed source, wrong migration hash or journal fields/types/precision/keys. This tranche supports workstation01 only. TABLE_NUM must contain exactly the original ID0 row; no counter normalization occurs. LOGICA must remain closed during preparation. DDL is nontransactional, each migration has a before/after journal entry, and an incomplete destination remains quarantined instead of being dropped/reused. No source is dropped, unlocked, migrated or written.

The additive eleventh migration creates the canonical checkout/full-return journals and adds missing writer-required fields to the original exported register01/journal/payment schema. All original columns and their rows are hashed before/after the copy and migrations. Every source table's DDL+rows is checked again through a fresh connection before Ready. A read-only job does not prevent another application from writing after Ready; closing LOGICA and switching applications remains necessary.

Acceptance project: `modernization/protected-copy-acceptance/ProtectedCopyAcceptance.csproj`. Arguments are repository root, official MariaDB bin and evidence root. Uses only its own disposable MariaDB33081 fixture. The source schema comes from original CREATE statements, never original shop INSERT data. It verifies real UTF8 data, actual AUTO_INCREMENT ID0 dump/import, first production cash checkout (counter/stock/payment/journal), operation replay, SELECT-only source, post-import injected failure, changed-source refusal, ID1 refusal, and dangerous destination/folder refusal. No installed shop has been accessed or accepted.
